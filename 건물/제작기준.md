# 건물 제작 기준

2026-11-09 사용자 확정 제작 원칙. 건물별 화풍·색채·용도·격식은 유지하면서 공통 시점과 구조 정렬을 지킨다.

## 건물 전체를 직육면체로 구성

**지붕의 축만 기준 각도에 맞추지 않는다. 건물 전체를 하나의 직육면체로 생각하고 지붕·벽·기단·바닥이 같은 지면 축을 공유하도록 만든다.**

1. 바닥 직사각형의 두 축과 네 모서리를 먼저 잡고 동일한 수직 높이로 외벽·기둥을 세운다. 먼 쪽을 작게 그리거나 소실점으로 선을 모으지 않는다.
2. 같은 방향의 바닥·기단 줄눈·벽 가로틀·문 인방·처마·용마루는 평행해야 한다. 바닥은 맞고 지붕이 돌아가거나, 지붕만 맞고 벽·기단이 비틀리는 원화를 그대로 채택하지 않는다.
3. 용마루는 해당 지붕을 받치는 본체의 중심과 일치시키고, 반대쪽 벽 높이·처마 돌출은 같은3차원 기준으로 정한다. 기울어진 지면·층고 변화가 별도로 설계되지 않았다면 임의로 만들지 않는다.
4. 지붕 경사면을 따라 내려오는 빗변은 높이 변화가 있는 선이므로 지면의 두 축과 평행하게 강제하지 않는다. 기와의 끝 장식이 들리는 것과 구조 축 자체가 휘는 것을 구분한다.
5. 문·창·난간은 각 벽의 평면과 축에 맞춘다. 정면 도안을 사선 벽에 붙인 것처럼 어긋나지 않게 한다.

## 공통 시점과 검토

- 기준은 사용자가 선택한 민가1의 측정 방향이다. 긴 벽·도로 방향A는 수평 기준 오른쪽 위 약21도(-21도), 짧은 측벽 방향B는 오른쪽 아래 약23도(+23도)를 목표로 삼는다. 좌표는 화면 오른쪽+x·아래+y다.
- 위에서 내려다보기 약24도는 원래 민가1의 두 지면 축에서 추정한 설명값이며 실제 카메라 메타데이터가 아니다.
- 용마루·처마·벽 가로틀·기단의 같은 방향 **직선 구간**을 각각 비교한다. 지붕의 기울어진 빗변이나 들린 장식 끝을 지면 축으로 측정하지 않는다.
- 각도만 보지 말고 같은 직육면체에서 나온 모서리·벽 높이·지붕 중심·앞뒤 규모가 맞는지 확인한다. 같은 단위의 인물·문·도로와 함께 배치해 검토한다.
- 128×64 논리 타일 투영은 화면 두 축 약±26.565도이므로 원화 목표21/23도와 동일하지 않다. 논리 좌표·그림의 접지·지면 표현의 관계를 실제 필드에서 확인한다. 그림을 비균등 확대하거나 화면상 회전해 불일치를 숨기지 않는다.
- 목표 각도와 제작 원칙은 필수 기준이다. 다만 현재 등록 원화는 수동 검토와 사용자 승인 자료이며 모든 선의 수학적 일치·실제 필드 통과를 검증했다고 간주하지 않는다.

## 형태·앞뒤·반전

- 깔끔한 F 일러스트풍과 도원의 기존 축척을 유지한다. 다양한 도시별 건물을 만들며 동일 원화·조립 부품 반복 사용을 필수로 하지 않는다.
- 특별한 용도가 명시되지 않으면 본채에서 돌출된 방·별관 같은 부속채를 임의로 추가하지 않는다. 작은 현관 차양(지붕·기둥)은 별도로 허용한다.
- 발코니는 제거 대상으로 일괄 금지하지 않는다. 격식 있는2층 민가1의 기존 앞면 발코니는 유지한다. 이 허용을 모든 건물에 새 발코니를 추가하는 근거로 쓰지 않는다.
- 앞·뒷면은 같은 본체와 층고·지붕을 공유한다. 후면에 정문이나 새로운 후문을 임의로 추가하지 않는다.
- 좌우반전은 각도 부호를 바꾸므로 비대칭21/23도 기준에서는 고정 도로 두 축과 완전히 일치한다고 보장할 수 없다. 반전 원화의 정문·접근·피벗·충돌·깊이 정렬도 함께 변환해 검토한다.

## 저장·적용

사용자 검토·승인 후에만 기존 원화를 교체하고 저장소에 올린다. 대상 파일·폴더를 먼저 알리고 새 폴더가 필요하면 이름·용도를 고지해 확인받는다. 중간 시안·검사 로그·전체 백업을 확정 자료 저장소에 일괄 올리지 않는다.

같은 파일명으로 원화를 교체해도 픽셀 피벗·문 좌표·표시 배율·충돌을 이전판에서 그대로 가져오지 않는다. 그림 외곽/처마·발밑 충돌·지붕 가림·정렬 기준·출입 판정은 별개로 관리한다. 원화 교체는 본게임 적용이나 심리스 구현 검증이 아니다.
