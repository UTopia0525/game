# 타일 배치 안내

사용자가 보관을 승인한 1차 타일 원화64장이다. **그림 등록 승인과 자동타일 사양·게임 적용 완료는 구분한다.** 실제 반복 배치·경계 맞물림·정확한 연결 끝점·최종 알파 정리는 아직 검증/보정이 필요하다.

## 폴더

| 폴더 | 내용 | 수량 |
|---|---|---|
| [기본바닥](기본바닥/) | 풀밭, 흙길, 돌포장, 밭고랑, 논, 수면, 목재 | 16 |
| [자연강변](자연강변/) | 자연 물가 직선, 육지 돌출, 물 파임, 완만한 흙 물가 | 16 |
| [석축수로](석축수로/) | 돌로 쌓은 물가 직선, 모서리, 통수구 | 16 |
| [논둑과다리](논둑과다리/) | 논둑 직선·모서리·분기, 급배수, 목교 바닥, 농지 진입 | 16 |

## 이름을 읽는 방법

모든 방향은 **화면 기준**이다. 파일명은 배치할 형태와 방향을 설명하며, 충돌·높이·자동타일 연결 데이터를 자동으로 지정하지 않는다.

```text
             위
       왼쪽위  오른쪽위
왼쪽                     오른쪽
       왼쪽아래 오른쪽아래
             아래
```

- `물오른쪽위`: 화면 오른쪽 위에 물이 보이는 경계. 직선이 뻗는 축과 물이 있는 방향을 혼동하지 않는다.
- `육지아래돌출` / `포장면위돌출`: 육지 또는 포장면이 그 방향으로 물 쪽에 볼록하게 나오는 모서리다.
- `물위쪽진입`: 위쪽에서 물이 들어와 육지/포장면을 오목하게 파고드는 형태다. 실제 상류·하류 지정과는 별개다.
- `왼쪽위-오른쪽아래`: 그 대각 축으로 뻗는 밭고랑·논둑·목교 바닥이다. 원화의 실제 줄 방향을 보고 이름을 붙였다.
- `논둑_모서리_물왼쪽아래`: 물이 주로 왼쪽 아래에 있고 논둑이 그 물가를 감싸는 꺾임이다.
- `논둑_세갈래_왼쪽위연결없음`: 왼쪽 위를 제외한 나머지 세 대각 방향으로 연결하는 분기 형태다. 최종 끝점 위치는 적용 전에 확인한다.
- `논둑_네갈래_모든대각연결`: 네 대각 방향으로 만나는 논둑 교차부다.
- `통수구`: 석축을 끊어 물이 통과할 자리를 표현했다. `급수구`는 논으로 물을 들이는 목제 수문, `배수구`는 논에서 물을 빼는 흙 수로 표현이다. 물 흐름은 별도 논리로 지정한다.

## 배치 원칙

1. 지형·물길·농경지를 먼저 정하고 도로·부지·건물·사물을 배치한다.
2. 시내 도로와 생활 마당은 돌/판석, 성 밖 길은 흙·자갈을 사용한다. 목재 바닥은 부두·데크 같은 용도로 구분한다.
3. 마른 밭과 물논을 무작위로 교대하지 않는다. 논은 취수→본수로→가지 수로→논→배수→하류가 이어지도록 배치한다.
4. 물길과 보행로가 교차하면 목교·통수구 등 실제 통과 방법을 둔다. 다리 위와 수면을 같은 보행 표면으로 취급하지 않는다.
5. 그림, 논리 지형, 수면, 보행 표면, 충돌, 높이·가림을 별도로 관리한다. 작은 모가 있는 논은 배경 원화이며 작물 성장·수확 기능을 뜻하지 않는다.

## 원화 규격과 확인 범위

- 각 파일은 투명 RGBA PNG, 원화 보관 캔버스314×314px다. 생성 시트의 칸을 분리하고 일부 칸에 투명1px를 패딩했다. 등록 과정에서 색·형태·해상도는 바꾸지 않았다.
- 기존 논리 타일의 화면 투영은128×64다. 원화 캔버스 크기를 게임 한 칸의 크기로 해석하지 않는다. 마름모 범위·원점·표시 배율은 실제 적용 시 맞춘다.
- PNG64장의 원본 동일성과 파일 크기/형식을 확인했다. 자동타일 인접 규칙, 반복 이음새, 연결 끝점, 아주 낮은 알파의 가장자리 색값 정리, 충돌·높이·실제 플레이는 아직 확인/보정이 필요하다.
- 경사·절벽·산길·동굴·계절·실내 바닥 및 도로와 풀/흙 사이의 혼합 경계는 이번 세트 범위 밖이다.
